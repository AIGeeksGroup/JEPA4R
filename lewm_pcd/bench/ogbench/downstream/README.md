The common downstream seam uses the original Cube distance GCDataset, GCIQL actor/critic/value/update, checkpoint transaction, boundary gate/reload, and serial Native evaluator. `trainer.py` changes only source locations/imports; its `run` function is unchanged. `sampler.py` replaces fixed widths with `latent_dim=192` and extends explicit Cube membership to 1..4. The sampler, goal RNG, distance reward and agent factory functions are unchanged. `native_core.py` changes only latent-width validation, Cube environment-name binding and explicit camera parameters. Its policy, capture, evaluator call, episode loop and scheduling functions are unchanged. Byte-preserved reference files and their source hashes are in `vendor/source_manifest.json`.

Public methods are `state`, `pldm`, `lejepa`, `lewm_rgb`, and `lewm_pcd`. LeJEPA means the canonical Tiny backbone followed by its 512-D head; its 16-D training projection is not a policy input. LeWM uses its original 192-D latent; the accepted Impala PLDM family uses its actual 512-D latent. A checkpoint from another PLDM architecture/output space is not interchangeable.

`build_command(profile_name, method, stage, data_root, output_root, config_path, python=None)` returns argv for `python -m bench.ogbench.downstream.runtime`. Set `PYTHONPATH` to the absolute checkout `lewm_pcd` directory, using the repository's normal training environment builder. This also works from another working directory. Supported stages are `gciql` and visual `native-sr`. The state policy is supported by the custom-distance training seam; state Native continues to use its original entry. The original official-state `bench/gciql/run_gciql.py` is unchanged and is a distinct protocol.

A recipe is required; this module never discovers a "latest" checkpoint. It must retain the original trainer fields (`seed=0`, `batch_size=1024`, `total_updates=1000000`, `resume_from=null`, validation every 5000, saves every 100000, heartbeat interval, role, agent config, accepted official-state split statistics and feature loader arguments) and add:

- `protocol: cube_all_distance_v1`, `cube_count`, `modality`, and `input_contract` with `zero_padding=false`. State widths are current `19+9N`, goal `3N`. Visual widths are current `L+19`, goal `L+3N`.
- `encoder_binding`: exact `family`, `latent_dim`, checkpoint SHA256 and, for visual methods, `checkpoint`, preprocessing source SHA256, input dtype/layout and selected device. Native PLDM uses the existing pinned adapter's `load_frozen`/`encode_uint8` API; LeWM uses its pinned `load_frozen`/`encode` adapter and original preprocessing source; Tiny calls the canonical CortexBench `load_lejepa` loader. Adapter paths and SHA256s are explicit. LeWM legacy adapters identify `adapter.api=legacy_lewm_v1`.
- `native_protocol`: `evaluator=ogbench_native_v1`, explicit matching horizon, full camera pose, `encoding_protocol=fresh_current_and_goal_each_policy_call_2N`, and optional original mode `diagnostic` or `full`. Cube2..4 preserve front/FOV45/local-X5/224/AA4 with explicit zero or 0.1-m pullback and PCD crop when applicable. Single uses its declared `front_pixels` source and render camera with zero extra pitch and zero pullback. Its position and FOV must be supplied by the actual cache/recipe and checked against the runtime source camera. The `single200` profile declares that identity; its historical pose remains `pose_runtime_verified=false`. N1 profiles without declared camera identity, including the metadata-only `official1`, fail closed for visual binding. No DoubleCube camera fallback is used.
- For Native, `native_protocol.policy` supplies the original training config, full acceptance report, gate batch and final policy checkpoint, including their SHA256 bindings. Native restores through the original boundary and checks the accepted complete policy state fingerprint. Offline and online encoder bindings, actual cache producer camera/preprocessing, family, width and manifest hashes must agree.

The `gciql` recipe `action` is `train`, `gate`, or `reload`; the latter two call the preserved two-update gate and independent reload functions. This merge does not run those commands automatically. It does not generate feature caches, migrate existing cache receipts, resume a formal run through a new scheduler, or claim formal results for a new task/encoder combination. Old entries remain available.

The command sets backend/RNG options before importing numerical libraries: `train` and `gate` use `JAX_PLATFORMS=cuda,cpu` and assert the original GPU backend; independent `reload` uses CPU with CUDA hidden. Native uses JAX on CPU and the frozen encoder on CUDA. The original non-partitionable Threefry, disabled preallocation, x64-off/default matmul precision and `--xla_gpu_autotune_level=0` are explicit. Visible CUDA devices default to the original logical selection `0`; a reviewed recipe may set `runtime.cuda_visible_devices`. The child must be a fresh process. The shared seam retains the original synchronous reference host-metric update hook; it makes no equivalence or throughput claim for the later `async100` monitoring wrapper.

Runtime execution requires the original Linux training dependencies, including Torch/JAX/Flax/OGBench and the frozen encoder's dependencies. The lightweight binding, projection, source-hash, AST and command tests run locally. A passing source/contract test is not a numerical, simulator, checkpoint-reload, performance or SR result.
