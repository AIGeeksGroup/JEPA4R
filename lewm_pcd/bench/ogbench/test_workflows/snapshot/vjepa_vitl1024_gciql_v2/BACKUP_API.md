These three new stdlib scripts do not import model/training modules or
deserialize pickle. Existing foundation, PLDM, GCIQL and encoder sources have
zero modifications by this backup implementation. Root owns deployment and
actual SSH/SCP validation.

## Invocation

The Linux metadata endpoint is invoked only by Root's local copier:

```text
python -B backup_watch.py --config REMOTE_BACKUP_CONFIG --action scan
python -B backup_watch.py --config REMOTE_BACKUP_CONFIG --action poststat
python -B backup_watch.py --config REMOTE_BACKUP_CONFIG --action ack
python -B backup_watch.py --config REMOTE_BACKUP_CONFIG --action failure
```

`scan` has no stdin; the other actions consume one JSON object on stdin.
`poststat` consumes `{snapshot: ...}`; `ack` consumes `{snapshot: ..., ack: ...}`;
`failure` consumes an error record. JSON stdout is separate from captured stderr.

On Windows, Root starts the persistent copier with explicit stdout/stderr
redirection and a saved wrapper exit code:

```text
python -B D:/LeWM_Artifacts/coordination/vjepa_vitl1024_gciql_31435_20261026_v1/release_v1/backup_copy.py --config D:/LeWM_Artifacts/coordination/vjepa_vitl1024_gciql_31435_20261026_v1/backup_config.json
```

`--once` performs one scan/copy cycle for the real pilot transport test. Without
it, a new scan follows 60 seconds after the previous cycle drains. One exclusive
`backup_runtime/worker.lock` prevents duplicate local workers. An abandoned lock
requires Root to inspect the old process before manually recovering it.

After the full queue has closed and all required D backups have passed Root's
independent check, Root may atomically create `LOCAL/backup_runtime/STOP.json` containing
`{"reason":"task_complete","expected_checkpoint_count":52}`. Only after the
current scan/copy cycle drains does the worker inspect this request. It requires
the exact 52 unique accepted checkpoint identities (four groups, pilot2 and
formal11 each), then records `phase:completed`, `checkpoint_count:52`, exit0 and
its normal immutable `worker_exit_*.json`. An early or invalid STOP fails closed
and retains failure evidence. Without STOP the existing polling behavior is
unchanged; the worker never stops or signals an experiment process.

SSH uses BatchMode, ConnectTimeout=90, ServerAliveInterval=30 and
ServerAliveCountMax=3. A metadata command has a 240-second total timeout; each
SCP command has a 300-second total timeout. The worker fails closed on timeout,
saves the actual error and never restarts an experiment or claims an unknown
child exit code as observed. There is no automatic retry or deletion of partials.

The existing serial queue adds this CPU phase after GPU gate/train:

```text
python -B backup_gate.py --config TRAINING_CONFIG --stage gate --report CASE/control/smoke/durability_reports/GROUP.json
python -B backup_gate.py --config TRAINING_CONFIG --stage train --report CASE/control/full/durability_reports/GROUP.json
```

The gate waits up to 600 seconds, polling local metadata every 2 seconds. A
sticky backup failure or bad binding fails immediately. `--timeout SECONDS`
accepts `(0,600]` only, for focused tiny timeout tests or a stricter caller.
This is a storage barrier; it changes no NN, optimizer or policy threshold.

## Checkpoint transaction and acknowledgment

Only the original committed
`OUTPUT/checkpoints/update_COUNTER/manifest.json` admits a transaction. Counters
are nine-digit directory names: pilot `[1,2]`; formal
`[1,100000,200000,300000,400000,500000,600000,700000,800000,900000,1000000]`.
All four groups therefore have 52 expected checkpoint transactions.

Each D copy is fresh:
`closed_checkpoints/{pilot|formal}/GROUP/update_XXXXXXXXX/`.
It contains the original `manifest.json`, `params_COUNTER.pkl`, `run_state.pkl`,
the exact `training_config.json`, command stdout/stderr/exit receipts, and one
immutable `receipt.json`. Payload SHA256 comes from the original manifest;
expected size and source inode/device/mtime/ctime come from live source stat.
Local SHA256/size must match; payload files and receipts are flushed. A fresh
remote metadata read must match all source stats/hashes before acceptance.

An accepted receipt records `schema_version`, `actual_exit_code:0`, the complete
source `snapshot`, `source_after_files`, `source_stable:true`, `local_files`
(SHA256 and stat), `copy_records` (actual SCP exits and argv), `completed`, and
`no_pickle_deserialization:true`. Partial paths and mismatched accepted paths
are preserved and rejected. Already accepted payloads use stat verification;
they are not repeatedly downloaded or hashed.

Only after that receipt exists and hashes successfully does the endpoint write
`ack_root/{pilot|formal}/GROUP/update_XXXXXXXXX.json`. Ack fields are:

```text
schema_version: 1
actual_exit_code: 0
group_id, stage, counter
config_sha256, manifest_sha256, snapshot_sha256
source_files, source_after_files  # exact original paths, SHA256 and stat/size
local_receipt_path, local_receipt_sha256
scp_exit_codes: [0,0,0,0]
```

Existing acks are accepted only if their complete contents are identical.
Any backup failure writes the sticky `failure_root/global.json`, blocking all
later durability gates. Local failures, partial bytes, source bindings and
transport logs remain available for Root's diagnosis. Backup failure never
signals, restarts or changes an experiment process.

## Closed small metadata

The scanner reads the actual `CASE/control/{smoke,full}/launch_plan.json` and
its named runtime phases. A phase is closed only when its `_exit.json` exists
and `residual_owned_members` is empty. It then copies the exact launch plan,
phase argv, combined log and exit record to `closed_logs/QUEUE/PHASE/` with the
same stat/SHA/size and source-after-copy receipt rules. Nonzero exits are
preserved with their real `phase_exit_code`; they do not become experiment PASS.

After a phase exits zero, `--report` is copied when present. Gate/train/Native
output roots use an explicit whitelist: report/status/resolved JSON, train CSV,
final state fingerprint, trainer exit, Native source binding, summary/source
binding. The audit phase copies `independent_audit.json`. Native's earlier
snapshot excludes that later audit file, preserving stable idempotency.
Each file is at most 16 MiB; raw data, vectors, episode NPZs and model/encoder
weights are excluded. Closed metadata has no training-release ack.

## Gate report and verification boundary

A successful gate report contains:

```text
schema_version: 1
actual_exit_code: 0
stage: gate|train
backup_stage: pilot|formal
group_id, config_path, config_sha256
checkpoint_count: 2|11
checkpoints: [{counter, manifest_sha256, ack_path, ack_sha256, local_receipt_sha256}]
completed, timeout_seconds, waited_seconds
progress: {expected_checkpoint_count, accepted_ack_counters,
           missing_manifest_counters, missing_ack_counters, checked_at}
```

Failure reports retain actual exit 1, traceback, timeout, elapsed wait and last
progress. They do not satisfy the serial phase. A backup receipt alone does not
prove CPU reload, training completion, finite model values or Native success;
the original downstream acceptance phases remain required.

Focused local tests use byte fixtures and a file transport, all below the fresh
D task directory. Root must still validate real SSH/SCP, a real pilot CP1/CP2,
the CPU durability report and the unchanged original downstream reload/Native.
