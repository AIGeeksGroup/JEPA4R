# 本次对照组的处理思路

本次是官方 Triple Cube state GCIQL：当前完整 state46、目标完整 state46，action5，全部FP32。使用原官方3000条训练／300条验证数据；不使用我们自采的600步世界模型数据，不加入视觉embedding、zero填充或mask。奖励和目标采样继续走官方索引规则。

处理流程：原官方数据由原compact loader读入只读RAM → 主线程按原sampler选择1024个样本及value/actor目标 → 一个后台物化线程按这些已确定的索引整理下一批 → 主线程按原顺序取batch并交给GPU做原GCIQL更新。最多提前一批，不启用这轮未证明稳定提速的双完整batch方案，也没有多个并行trainer。采样及NumPy随机数仍由主线程控制，后台线程只读取数组。

初始化的一个示例样本沿用原方法。验证、保存和原评测节点前收齐预取，并保持对应随机数状态。每5000步仍按原流程记录训练指标并取一个验证batch；没有改变算法、学习率、精度、batch、网络或训练预算。原配置seed0、B1024、1M更新、Triple alpha1保持。

按用户最后确认的时间安排：第1步先保存一份，之后每100K保存一次，共11份原格式checkpoint。训练中不运行环境评测，只保留原评测节点的必要随机数记录；100万次更新结束后，依次重载11份checkpoint，执行原官方评测代码：5个任务各50条统计轨迹、每任务另1条视频、max1000步，CPU评测、temperature0及原成功判定。评测使用同一环境及相应随机数记录；没有改成旧自定义Native配对协议。

原官方源码文件保持原字节。新显式入口只在内存AST替换延期评测位置、增加首步保存条件，并转发已验收读取器、数据路径和离线日志。全部参数、源版本、实际argv、状态、CSV、checkpoint侧票据和退出码持久保存在本任务独立目录；最终完成和SR仍以真实退出及完整结果为准。
