# Bounded Cube gate interfaces

These interfaces add evidence and recovery around the existing Cube implementations. They accept only explicit `mode: "smoke"` and one/two total optimizer updates. A plan does not load Torch/JAX, execute a model, or create the output directory. Execution requires `--execute`; output directories and state files must be new.

```bash
PYTHONPATH=lewm_pcd python -m bench.ogbench.gate_checks \
  --stage STAGE --config /absolute/case.json --output /absolute/new-case --execute
```

Every execution writes its configuration SHA, source-file SHA, stdout/stderr, RESULT.json and actual_exit_code. A comparison failure exits nonzero and preserves its error metrics. These receipts do not replace the shared R0–R6 inventory or certify an unrun gate.

## D2 collection

The existing collection CLI adds `--resume` and repeatable `--part-id`. Canonical physical part IDs, task/strategy order, world/policy seeds and the original collector remain unchanged. Explicitly selecting a completed part rejects duplicate execution. Recovery validates immutable ACCEPTED.json receipts and their exact data paths/hashes, retains failed attempts, and runs missing parts in new attempt directories. A prior attempt lacking an exit receipt is refused until the operator inspects its termination; this is not permission to run another copy concurrently.

Selecting a strict subset produces `cube_collection_partial_v1` with `complete: false` and no COLLECTION.json. Final merging always uses the full canonical part order. The original VDS merger and actual HDF QC remain in use. Complete receipt identity is bound to status and cannot redirect the merged paths on resume.

## T4 Tiny

Stage `tiny-step` invokes the same native Tiny main/forward/loss/optimizer loop through an explicit gate observer. The ordinary main call has `gate=None`; the original augmentation loader and BF16 loop remain its default. The gate consumes real, already-augmented fixed batches and their original IDs; it does not claim arbitrary multiworker prefetch/augmentation queue recovery.

The configuration contains:

- `mode: "smoke"`, `model: "lejepa"`, `stop_after: 1` or `2`, `seed`, `precision: "bf16"` or `"fp32"`.
- `dataset`: the original dataset provenance string, `loader_samples` and `loader_batches_per_epoch`: the actual native small-data counts. Batch256, four views and the native ten-epoch scheduler are retained.
- `batch_arrays: {"path": ..., "sha256": ...}`: NPZ containing at least three real consecutive augmented batch tensors, each FP32 `[256,4,3,224,224]`. The third identifies the next batch after update two.
- `batches`: ordered objects `{"id": ..., "array_key": ..., "epoch": ..., "batch_index": ...}`. IDs identify events and retain the actual row IDs in the R3 input inventory.
- `identity`: model=`lejepa`, data=the NPZ SHA, config=the frozen training recipe SHA, split=`train`, action_dim=5. The identity remains the same across continuous/first-step/resume controls.
- Optional `initial_checkpoint: {path,sha256}` for an original native backbone/head/proj export; for an old/new fixed-state comparison use `initial_training_state: {path,sha256}` from the passive old recorder's initial_state.pt, including original optimizer/scheduler/scaler/RNG before every update. Optional `resume_state: {path,sha256}` resumes this gate's step_1.pt. Restore also requires the immutable `.pt.json` receipt; a step0 initial state must have cursor0 and is never reseeded afterward.

Restore validates the committed step against the fixed cursor, next batch ID and next entry's epoch/batch index before returning to the native loop. The cursor must remain below `stop_after`, and a next-entry descriptor must exist through the final requested boundary. Completed or inconsistent checkpoints reject before any new forward/update; use the completed-state comparison/reload path for them.

Run continuous update two, first update one, and an independent resumed update two into three new directories. Each successful step writes full named outputs/losses/gradients/before-after parameters, plus encoder+SIGReg buffers, Adam, scheduler, scaler, all RNG and next-batch cursor in a full checkpoint. Stage `compare-resume`, `kind: "torch"`, consumes pinned `actual_state`/`reference_state` step_2.pt and compares the entire state tree exactly using the shared comparator.

## T4 GCIQL

Stage `gciql-step` consumes `runtime_recipe: {path,sha256}` from the accepted small official cache, `stop_after` 1 or 2, and optional `resume_root` pointing to the first gate's `gate` directory. It reuses the original prepare/initial_agent/update/save_boundary/restore_saved implementation. Restore verifies actual source/cache bindings, applies the saved host RNG, and compares the next complete batch and raw IDs before updating. The declared formal recipe remains frozen; this gate's loop is hard-bounded to at most two actual updates and never starts the formal trainer.

Outputs include the original reports/checkpoint transaction, full_state.npz with all named Flax agent/Adam/JAX-RNG leaves, and next_batch.npz/next_ids.npz. `compare-resume`, `kind: "gciql"`, requires pinned `actual_state`, `reference_state`, `actual_next_batch`, `reference_next_batch`, `actual_next_ids`, `reference_next_ids`, plus `actual_sidecar`/`reference_sidecar` (run_state.pkl) and `actual_checkpoint_manifest`/`reference_checkpoint_manifest` (manifest.json). Each binding is `{path,sha256}`.

The one/two-step gate also saves the complete GPU `next_actions.npy` for this same next batch, temperature0/key0, with full-agent and host-RNG invariance checks. Its report stores parameters-only initial/final fingerprints and requires actual parameter changes. GPU checkpoint replay can be compared on the same GPU stack. GPU-to-CPU differences are retained as cross-backend diagnostics and are not promised the guide's same-CPU tolerance.

Stage `gciql-cpu-reference` accepts the pinned runtime recipe plus `gate_root`, independently reconstructs the actual terminal `full_state.npz` using the original factory, and verifies all153 leaf paths/shapes/endpoint dtypes/values and the actual terminal fingerprint before a CPU temperature0/key0 forward. It writes `CPU_REFERENCE.json` and complete CPU actions. The descriptor pins producer report, raw-state export, next batch/IDs, recipe/config, original math/library identities, current observer source and every state-leaf identity. It explicitly labels a new CPU reference derived from actual training-end raw state, not the original GPU output.

Guide `gciql-reload` requires this pinned `cpu_reference` descriptor, separately restores `params_N.pkl` in a fresh CPU process with zero updates, retains full153-state/next-batch/raw-ID checks, and compares all5120 actions on the same CPU stack at atol1e-6/rtol1e-4 with max-error/outlier counts. It cannot pass on shape/finite alone. The ordinary original workflow `reload` call leaves `cpu_reference=None` and keeps legacy checkpoint/next-ID/finite compatibility, explicitly reporting that same-CPU consistency was not checked; any GPU comparison remains a diagnostic. No threshold, matmul setting or original GPU action file is rewritten.

Before unpickling an owned checkpoint sidecar, comparison verifies both manifest pins, agent/sidecar transaction checksums and the completed two-update counters. It then compares the entire sidecar tree, including Python/NumPy/Torch CPU/CUDA RNG, source/data/config bindings and event metadata, without dropping fields. Complete agent arrays and next batch/IDs still compare exactly. The frozen recipe has constant optax Adam and JAX FP32, so scheduler/AMP scaler are explicitly reported as not applicable; unexpected nonempty state for either is refused. These tests do not replace a real GCIQL continuous/resume execution.

## Lightning state boundary

LeWM and PLDM `run` accept optional `resume_checkpoint` and `state_callback`, forwarding to the existing SPT Manager/Lightning path. `training_state.lightning_state_callback(identity, cursor)` adds strict identity, RNG and optional fixed-batch cursor to the existing full Lightning checkpoint. The existing model/optimizer/scheduler are preserved; PLDM's existing schedule callback retains its actual step index. These hooks require a real continuous/resume model run to validate; a generic state-helper unit test is not that evidence.

The explicit `python -m bench.ogbench.cube_recovery --method {lewm_pcd,lewm_rgb,pldm} --data-manifest /absolute/data_manifest.json --output /absolute/new-run` entry plans the original two-update smoke with workers0. `--execute` calls the original LeWM/JEPA4R `native.run` or PLDM `train.run`, using the shared, SHA-frozen `bench.relocate.recovery.stateful_loader_class` and callback. It retains the original seed0, batch128, factory, BF16, optimizer, scheduler and original data transformations. It never implements a second training loop. The temporary loader aliases and Manager wrapper are restored on exit; the default original entry is unchanged.

Run continuous with no recovery flags, pause with `--pause-after-batches 1` (a verified sealed checkpoint and process exit75), and resume independently with `--resume-checkpoint /absolute/first/recovery/pause_batch_0001.ckpt`. Resume uses the original Manager's `ckpt_path` and `weights_only=False`; a checksum/identity mismatch is refused. The shared callback records full inputs/sample order, explicitly restores the materialized loader after SPT's early scheduler setup, then restores complete RNG after the sanity pass. Completion requires a sealed final.ckpt at actual global_step2. Compare full model/buffers, Adam, actual scheduler, Python/NumPy/Torch RNG, loader/generator/order, global progress, native PLDM schedule metadata and complete callback input/loss/next-ID records. Independent small CPU SPT fixture evidence is separate from the still-required production-model T4 execution.

Stage `compare-resume`, kind=`lightning`, consumes pinned actual_state/reference_state final.ckpt plus pinned expected_identity pointing to the producer's RECOVERY_IDENTITY.json. It verifies both sealed exit0/two-update checkpoint receipts and trusted identity, then compares the entire checkpoint tree exactly, including all loop state, hyperparameters and custom callback fields. Distinct SPT run directories are reported and aliased to `$SPT_RUN` only inside their own actual run root. Original Lightning ModelCheckpoint ±Inf selection sentinels retain their full dtype/shape/byte identity in explicit metadata; NaN or paths outside the run reject. This exception does not apply to model/optimizer/loss arrays. No checkpoint fields are discarded. Every alias/sentinel and every mismatch remains in the comparison result.

For retained Cube1 raw inputs, `python -m bench.ogbench.retained_training --collection-root ... --baseline-root ... --expected-receipt-sha256 ... --expected-baseline-manifest-sha256 ... --metadata-file .../LICENSE --metadata-file .../pyproject.toml --output /absolute/new-import --execute` derives new VDS files and a `TRAINING_INPUT_IMPORT.json`. It verifies all six original raw byte hashes and aliases every available original producer file by identical content. It keeps the entire original producer binding and receipt immutable; it does not declare new collection. Known unavailable old SWM metadata is explicitly listed, and unavailable original Python/unknown metadata rejects. When the exact two historical metadata files are supplied, all228 original producer identities can be verified without replacing the current vendor files. Every merged VDS source/order and every training-view terminal-row exclusion is checked. The optional retained_import field adds this validation to `fresh_data.load_binding`; ordinary manifests retain their existing path.

## M1/M3 full arrays

Stage `model-numerics` supports `model: "lewm_pcd"`, `"lewm_rgb"`, `"pldm"`; it calls the existing factory and original forward/loss, observes prediction output, retains every named parameter and gradient, and performs one positive-LR FP32 update with the original optimizer/clipping. This is an M3 fixed-state update, separately from the native BF16 T1 path.

The PLDM numerical branch reads the actual original forward_result once and retains its full encoder/predictor/action tensors, alongside all original loss outputs. It returns the unmodified ForwardResult to the inherited loss code, with no extra model forward or random draw. Cube PLDM is original Impala512/RGB16/A15 with active IDM; it is distinct from Native PLDM's ViT/disabled-auxiliary configuration. A fixedB2 M3 input keeps the configured author scheduler batch128/epochs10/train_batches; do not rescale LR forB2. Its source/factory/preprocessor/window and train-only action statistics must be the real paired-data producer's.

Inputs are pinned `checkpoint`, `batch_arrays`, plus `source_revision`, `source_root` (repository directory), `source_manifest_sha256`, `expected_source_files` (relative to lewm_pcd), `seed`, and `device`. Actual imported source-root, manifest and module-file hashes are checked and reported. LeWM/JEPA4R require `model_config` pointing to the full effective recipe (not the encoder-only factory JSON). The batch contains the original model-input keys and normalized actions. Their optimizer uses the production SPT Module parameter-group collector and SPT create_optimizer factory, including its real bias/norm-decay/default configuration; complete group membership/options and installed factory/module source SHAs are recorded. PLDM uses its original optimizer and requires its actual `train_batches` and frozen `schedule_step`; zero learning rate is refused for M3. `numerics.npz` retains output tensors, unclipped/clipped gradients and complete before/after parameter arrays.

Run the producer against the frozen old implementation and the new implementation in isolated processes with identical actual weights/input/mode/RNG/precision; retain each source identity independently. Stage `compare-numerics` consumes pinned `actual`/`reference` NPZ files, uses elementwise atol=1e-6/rtol=1e-4 and the complete parameter-delta relative-L2/cosine checks. This stage must not compare two new self-generated outputs and call that old-version equivalence.

To observe the old implementation without copying this helper into its source tree, invoke this same observer as a direct script in a fresh process with `--source-root /absolute/reference/baselines/cube`. It imports that old bench.ogbench package first; all relative training_runtime/native/jepa imports then resolve there. The configuration's expected root/file/manifest hashes must agree. The helper's own SHA remains distinct from the actual model-source SHAs.

For old Tiny, use `tiny_inputs.py` as a direct CPU-only script to create three fixed real augmented batches with f437's original Frames/DataLoader/torchvision transforms from the retained paired RGB train view. No model is constructed during this preparation. Use `tiny_reference.py` as a direct script with its generated config: it verifies the exact f437 native module SHA and a zero-argument original main, calls that original main/Encoder/AdamW/SequentialLR/GradScaler, and only substitutes the explicitly frozen augmented input stream. An external Python trace reads the original locals before forward and after the original scheduler step. It saves step0/1/2 complete states and actual outputs/gradients/parameter increments, then exits at the verified two-update boundary. It neither calls new main(gate) nor copies its training/loss implementation. Native ten-epoch completion and arbitrary multiworker-queue recovery are not claimed. The independently recorded step0 state is the new Tiny gate's initial_training_state input.

The separate Tiny CPU FP32 M3 fixture is selected only by `numerical_fixture: {schema: "cube_tiny_cpu_fp32_M3_v1", role: "M3", configured_batch_size: 256, actual_fixed_batch_size: 2}`, together with precision=fp32, stop_after=1 and seed0. It consumes the first two real samples/four views from the frozen augmented inputs and retains their row IDs. Original main arguments, loader-length metadata, learning rate, weight decay, AdamW and ten-epoch scheduler formula/timing stay configured for256; actual fixed model input is explicitly B2. The same external device fixture is applied to both original main routes: original Encoder/SIGReg `.to(cuda)` routes to CPU, the original SIGReg `randn(device=cuda)` routes to CPU, autocast is explicitly disabled, and the original scaler is disabled. Factories inherit the original init/forward without copying arithmetic. NUMERICAL_FIXTURE.json records the mapping/source SHA and configured-versus-actual batch sizes. This numerical-only branch does not change the ordinary Tiny CUDA/BF16 batch256 path or certify its floating-point resume equality.

The numerical CPU T4 continuation is a separate default-off role: schema=`cube_tiny_cpu_fp32_fixed_batch_v2`, role=`T4`, configured_batch_size256, actual_fixed_batch_size2, precisionFP32, stop_after2 and seed0. Its mandatory continuation_source pins the accepted original M3 recipe, sealed first-state and receipt, original initial-state, first producer result, source freeze and accepted comparison case. Training identity/data/config hashes remain the original hashes only after the unchanged math recipe, batch IDs, loader/scheduler lengths and original producer chain validate. This permits reusing the real prior first1 checkpoint: execute fresh continuous2 and independent resume1 into new directories, adding three CPU updates. Compare continuous step1 against the reused first1 and continuous step2 against resumed step2 as complete trees. Original records remain immutable. The scaler is explicitly disabled on CPU; CUDA AMP continuity and the prior BF16 floating-point comparison retain their separate results.

## M2 24 real forwards

Stage `matrix-forward` requires exactly the 24 unique model/Cube pairs in `cases`. Every case provides pinned `downstream_config` (accepted smoke encoder binding), pinned `inputs` (current_visual/goal_visual/current_state/goal_state), pinned `policy_config`, and `policy_checkpoint: {path,counter,sha256}`. The checkpoint SHA covers params_COUNTER.pkl; every policy and encoder is actually loaded. Policy inputs use the original CubeInputs seam and original GCIQL factory/action forward. Identical encoder model/weight pairs share a single load across four Cube inputs; per-case outputs still include complete latents/current/goal/action NPZ arrays. This gate does not substitute synthetic zero features or pad dimensions.

An explicit default-off `source_encoder_config: {path,sha256}` may select an actually accepted encoder from another Cube. The unchanged original `_assets` checks that source's real producer, data, checkpoint, preprocessing and factory. Source and target must have identical complete encoder bindings/model/mode; any target receipt/import must refer to that same source. The encoder is constructed from the validated source runtime. Target configuration validation, actual state width `19+9*N`, current prefix19, goal XYZ for each of N Cubes, camera and policy contract still use the target. This does not create or relabel target training evidence. Cache reuse keys include the complete factory/preprocessing binding as well as the model.

Each shared-source case also requires pinned `input_provenance` with schema `cube_matrix_target_inputs_v1`, its target `cube_count`, exact target `camera`, exact `inputs` pin, `producer_receipt` pin, `source_arrays` pin and four `rows`. Each row maps one of current_visual/goal_visual/current_state/goal_state to `{key,row}` in the real source NPZ. The producer receipt must have actual integer exit0, target cube_count/camera, `raw_inputs` equal to the source NPZ pin, and nonempty `source_binding` mapping actual producer files to full SHA256. The gate checks these files and compares every selected source array's dtype, shape and complete bytes with the fixed input. Wrong Cube, camera, swapped rows, changed source, failed producer, nonfinite states or malformed RGB/PCD reject before encoder construction. This descriptor is a separately produced input witness; it never edits the original data or encoder receipt. No-pin cases retain the original target asset loader and do not infer a new provenance claim.

Full matrix execution requires that provenance for every case, together with `input_selectors: {current: {raw_row_id: ...}, goal: {raw_row_id: ...}}`. The source NPZ supplies an int64 `raw_row_ids` vector, bound to the producer's `raw_rows`. Visual and state must select the same snapshot index within each phase, and that index must resolve to the declared canonical physical row. A compact snapshot index1 can represent physical row200/500/1000/600; it is never treated as that physical ID without the map.

Each policy configuration declares model, method, role=`MODEL_cubeN`, cube_count, seed0, original input_contract and complete encoder_binding. A pinned `policy_origin` (`cube_M2_policy_origin_v1`) binds that effective config, checkpoint and inputs to the actual frozen producer case ledger/result/observer. Those records and params_COUNTER.pkl must be covered by the producer's original reference freeze. The effective config may add identity metadata while preserving every original scientific configuration field; its `source_policy_config` pins the original actual config. A matching shape or checkpoint SHA alone cannot exchange RGB/PCD or other same-width roles. Archived data can use explicit full-byte aliases for CPU checking and a new supplement, leaving original producer records unchanged.

M2 retains the original `restore_agent`. Before it runs, the gate checks the pickle envelope and every dictionary/sequence key, including empty containers, against the real factory template. `state_replay` checks every numeric leaf's path, shape, dtype and finiteness, recording the existing integer-counter dtype allowance. After the original restore, the complete serialized agent tree must match the actual saved state byte for byte. Each case also writes its full policy-state NPZ; a missing/extra key, changed buffer, wrong shape/dtype or nonfinite value rejects before the policy action. The counter0 fixture initializes the original factory from actual encoded inputs and saves/reloads that real initial state; it is explicitly an untrained interface diagnostic. A single future-goal frame from the same real episode is a fixed M2 input, with no change to formal evaluation goal semantics.

The original local LeWM loader requires an explicit fresh `CUBE_WORKFLOW_FACTORY_CACHE` directory. Set that environment variable for a standalone M2 invocation; the frozen external M2 runner supplies its own per-role directory. Old-source recording keeps the actual source paths and hashes separate from observer code, including the original shared Tiny loader retained from the Adroit baseline and the PLDM metadata-key-only repair. Source receipts and prior failed attempts remain unchanged.

## E1 trace

The existing smoke Native path enables passive state tracing; formal defaults remain unchanged. The original evaluator still owns reset/action execution. `trajectory.npz` contains T+1 qpos/qvel/ctrl/time/observations and T policy latents/current/goal/proposed actions/executed actions/reward/success/termination events with explicit frame IDs. Native audit checks its byte SHA, finite arrays and row/input/action alignment. The trace adds no physics step, random draw or encoder call. Actual simulator execution and R5 comparisons remain required.
