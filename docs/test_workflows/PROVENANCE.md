## 文件来源

`lewm_pcd/bench/ogbench/test_workflows/source_map.json` 为每个原生相对路径记录 SHA256、字节数、原始 mtime 和仓库文件位置。`snapshot/` 中的文件是冻结参考，不是新的一套算法实现。

若字节与已有 v3 文件一致，直接引用已有文件；相同内容的多个原生路径也只保存一份。材料化时还原各自原始文件名，因此原始源码 SHA 守卫仍有可核对的字节依据。原生学习器和训练循环没有为本次目录整理重写。

原始 `catalog.json` 中每个已记录阶段都指向来源计划和数组位置；配置中的命令指向原字段。较早的 State/LeWM 原生入口、Single RL3 迁移参考与新 Foundation/Tiny 启动链保留各自来源，查询状态区分“原始命令已留存”和“原生代码/配置已收录”。

## 历史版本

v3 的源清单和验收记录保留在 `evidence/unified_v3/`；更早版本的记录沿用原目录。当前版本使用新的完整源清单和代码验收记录，不通过更改旧 PASS、旧退出码或旧哈希来证明新版本。

部分文件路径带 `v1`/`v2`，仍是较新 wrapper 用 SHA 精确导入的依赖。这类文件保留在冻结源码中，不按名称推断为可删旧版本。源快照不纳入无引用的 scratch、失败候选副本和当前任务之外的实验数据。

## 清理边界

本次验证之后只清理由本次任务产生、已确认无用的失败克隆或冗余中间包，并保留其失败原因、哈希和退出信息。原始 Test 训练数据、checkpoint、日志、已验证缓存和历史实验失败证据保持原状。不能确定是否仍有引用的服务器旧目录，需先列明路径和用途再请用户确认。

## 更新方式

更新原生实现时，先冻结新 source/config/依赖，再更新来源映射、分组配置和阶段引用；重新运行受影响的代码检查。模型或协议变化需要对应数值/行为证据，不能用索引检查通过代替训练或评测验收。
