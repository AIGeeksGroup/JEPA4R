# Native RH56 Relocate: optional data and learning adapter

This is the native RM75-B/RH56 interface used by the completed 2026-10-25 experiment: expert observation56, proprio13, actual action12, 100Hz and at most200 steps. It is separate from the older 20Hz/13D `SCRIPTED_UNQUALIFIED` archive. Do not substitute that older controller or its assets.

The existing Adroit entrypoints and shared learning sources are unchanged. RH56 is enabled only by explicitly calling `lewm_pcd/scripts/run_rh56.py`. The adapter selects the repository's existing RGB or DexArt PointNet model configuration and delegates to `train.run` and the official `bc_pvr_train_loop`; it does not implement another optimizer, loss or BC learner.

## External inputs and environments

Keep datasets, checkpoints, expert weights, simulator assets and licenses outside Git. Provide:

- `RH56_EXPERT_ROOT` or `--expert-root`: the original native bundle, including `env.py`, `ppo.py`, `experts/relocate_expert.pt` and the model/assets referenced by that environment. Source and expert checkpoint hashes are recorded by collection. This repository does not redistribute the bundle or pretend the old scripted archive is a replacement.
- The original native simulator requires **MuJoCo3.12.0**. Keep native data/simulation dependencies separate from an existing Adroit MuJoCo200 environment. WM training itself does not require the RH56 simulator.
- `CORTEXBENCH_EAI_VC_ROOT` or `--eai-vc-root`: the existing eai-vc checkout containing `cortexbench/mujoco_vc/visual_imitation/train_loop.py` for BC. Follow the repository's existing versioned WM/BC dependency instructions; this adapter does not replace either environment's dependency set.
- `--baseline-root` optionally selects an existing compatible LeWM source/config root. Its default is this checkout's `lewm_pcd` directory. There are no deployment-specific server, Nix or license paths in the adapter.

Run the commands below from `lewm_pcd`, using the appropriate existing Python environment. All `PATH_TO_...` names are external user-supplied paths. Outputs must be fresh, outside protected source directories; existing outputs are never silently overwritten.

## Explicit stage and modality switches

```bash
python scripts/run_rh56.py --help
python scripts/run_rh56.py wm --route rgb --dry-run --dataset PATH_TO_RGB_HDF
python scripts/run_rh56.py wm --route pcd --dry-run --dataset PATH_TO_PCD_HDF
```

No stage means help only. Help and `--dry-run` do not import or execute learning/simulator backends. `--route rgb|pcd` (alias `--modality`) is required for WM/BC; collection always produces paired modalities. Other arguments are forwarded to the selected stage. Explicit external-path options may appear before or after the stage.

| Stage | Reused boundary | Key inputs |
|---|---|---|
| `collect` | native expert, original feedback mix, paired HDF writer | frozen episode plan, external native bundle |
| `validate` | deep paired batch/data contract | completed direct batch, optional original plan |
| `publish` | relative-path VDS headers, no source rewrites | accepted batches and expected split counts |
| `official-init` | same native collector with task-position-only reset adapter |100 ordered official task initial states and source SHA |
| `wm` | original world-model training entry | paired HDF header, matching episode manifest, route |
| `bc` | original frozen-encoder CortexBench BC | corresponding WM checkpoint, accepted demo manifest, route |

## Paired collection and VDS publication

The formal camera default at the public entry is `opposite`: position(0,1.2,1.2), FOV45, RGB256/MSAA8 and PCD1200/NoAA with matched actual extrinsics. The lower-level collection module retains its explicit native-camera option for diagnostics. Point sampling/crop/voxel formulas and native physics/expert control are reused.

An episode-plan JSON contains `episodes`, for example:

```json
{"episodes":[
  {"split":"train","seed":61000000,"coverage":"protocol"},
  {"split":"val","seed":62000000,"coverage":"protocol"}
]}
```

`protocol` delegates the original natural50/30/20 draws; `expert` selects a pure expert rollout. Seeds and physical initial states must be unique. Keep failed mixed episodes. Collection stores T actual actions with T+1 observations; the paired HDF action's final row is the declared all-NaN terminal sentinel, not another executed action.

```bash
python scripts/run_rh56.py collect --expert-root PATH_TO_NATIVE_BUNDLE \
  --plan PATH_TO_PLAN_JSON --output PATH_TO_FRESH_BATCH

python scripts/run_rh56.py validate --batch PATH_TO_FRESH_BATCH --plan PATH_TO_PLAN_JSON

python scripts/run_rh56.py publish --batches PATH_TO_ACCEPTED_BATCH_1 PATH_TO_ACCEPTED_BATCH_2 \
  --output PATH_TO_FRESH_PUBLISHED_DATA --expected-counts '{"train":9000,"val":1000}'
```

Validation produces a deep `batch_acceptance.json` receipt and rejects overwriting an existing receipt. To recheck, provide an explicit fresh `validate --output NEW_RECEIPT.json`. Publication verifies the accepted direct-batch evidence and writes only VDS headers/manifest, leaving original HDF/NPZ data intact. VDS relative source paths must remain resolvable; moving a header alone is insufficient.

## WM: same learner, explicit RH56 data boundaries

```bash
python scripts/run_rh56.py wm --route rgb --mode formal --device cuda \
  --dataset PATH_TO_PUBLISHED_RGB_HDF --manifest PATH_TO_PUBLISHED_MANIFEST \
  --output PATH_TO_FRESH_RGB_RUN --workers 24 --prefetch-factor 2

python scripts/run_rh56.py wm --route pcd --mode formal --device cuda \
  --dataset PATH_TO_PUBLISHED_PCD_HDF --manifest PATH_TO_PUBLISHED_MANIFEST \
  --output PATH_TO_FRESH_PCD_RUN --workers 24 --prefetch-factor 2
```

Both routes use B128/BF16 mixed, history3+prediction1, frameskip5 and10 epochs. RGB uses the repository ViT-tiny/14; PCD uses its DexArt PointNet. The latent width192, predictor/projector, loss, AdamW and scheduler follow the existing configurations.

RH56's whole-episode train/validation partition and train-only normalizer fitting are explicit adapter behavior; they replace the old clip-random boundary for this task only. They do not change existing Adroit defaults. Fingerprints record their learning-source scope and exclude mutable outputs/caches; adapter hashes are separate. Do not apply an old standalone run's sealed resume receipt to this packaged version. `--resume` remains experimental: exact sampler/RNG continuity was not established by packaging tests.

### Experimental image transfer optimization

`--uint8-gpu-preprocess` is **off by default**, valid only for RGB/CUDA, and reuses the original image transform through the existing SPT transfer hook. The original image/RNG check passed, but the full-model CPU/GPU numerical-equivalence gate failed and remains failed. Explicitly enabling this option does not imply numerical equivalence. PCD does not use the image hook. Prefetch is limited to1–3.

The historical RGB production run used this explicitly enabled option; default-off packaging is therefore not an assertion that rerunning the default command reproduces that run bit for bit.

## Official task initialization to native RH56 BC data

The input `official-task-init-v1` JSON contains100 records in official order0..99, a preserved official source-manifest path/SHA, and per-record `demo_index`, `source_id`, `original_init_sha256`, `obj_pos` and `target_pos`. Coordinate vectors are three finite numbers. Keep the original full initialization and source-file hashes as provenance.

```bash
python scripts/run_rh56.py official-init --expert-root PATH_TO_NATIVE_BUNDLE \
  --init-source PATH_TO_ORDERED_OFFICIAL_INIT_JSON --init-source-sha256 FROZEN_SHA256 \
  --output PATH_TO_FRESH_NATIVE_DEMOS --seed-base 64500000 --start-demo 0 --count 100
```

Only object/target task positions are transferred. The adapter first performs the native reset, checks that qpos/qvel/ctrl/act and drive state are unchanged after injection/forward, returns a fresh observation, then delegates to the original expert/collector. Adroit joint state, action or visual features are never reused as RH56 training targets.

All requested source indices and failed attempts are retained without resampling. A new `bc_demos_manifest.json` exposes all attempts; it becomes a usable selected manifest only when all requested sources succeeded.100 complete successful records are required for formal BC. An incomplete or rejected source set must not be silently replaced or filtered to manufacture100 successes. `--start-demo`/`--count` support explicit bounded source slices, not random replacement.

## BC: frozen corresponding model, original training loop

```bash
python scripts/run_rh56.py bc --route rgb --mode formal --device cuda \
  --expert-root PATH_TO_NATIVE_BUNDLE --eai-vc-root PATH_TO_EAI_VC \
  --checkpoint PATH_TO_RGB_CHECKPOINT_DIRECTORY --epoch 10 \
  --demos-manifest PATH_TO_ACCEPTED_100_DEMO_MANIFEST \
  --train-seed 100 --out PATH_TO_FRESH_BC_RUN
```

For3D, switch to `--route pcd` and the actual PCD model directory. Repeat separately with head seeds100/200/300. The original MLP/FLARE3+proprio13→action12/MSE/Adam loop remains unchanged:100 demos,100 epochs, batch256,25 online trajectories per evaluation. Official loop indices5,10,…,95,99 produce20 evaluation rounds. Evaluation seeds are independent of demonstration seeds.

RGB BC retains its original PIL bicubic resize→ToTensor→Normalize path; RGB WM uses its original normalize→bilinear resize path. PCD geometry/color normalization follows its saved checkpoint. These existing paths are not silently unified, and modality comparisons do not establish a causal attribution to input dimensionality alone.

The paired2048-frame screening found no obvious overall/constant representation collapse in either model; it did not guarantee downstream success. [Integration/interface validation](rh56_native_20261025_validation.md) is recorded separately. Tests do not collect new data, retrain the world models or claim to reproduce six SR runs. Keep state, logs, actual exits, input/source hashes and full/bare model evidence with any future long run.

### Training and offline inference handoff

The supplemental code connects the existing components without replacing the original learner:

- `code/rh56_inference.py` assembles the saved point-cloud transform, encoder/projector, original FLARE history fusion, proprioception and selected BC head. It exposes episode-history reset and returns raw action means, without creating a simulator or sending commands.
- `examples/infer_sequence.py` accepts NPZ arrays `clouds(T,1200,6)`, `proprio(T,13)` and optional `reset(T)`, and writes raw action means `(T,12)` to a fresh output file. `--self-check` uses generated synthetic inputs only.
- `code/load_world_model.py` strictly reconstructs the complete JEPA model, including all 111 state-dict entries. It supplies parameter initialization; it does not resume an optimizer or data sampler.
- `code/vendor/` preserves the actual stable-worldmodel, EAI and MJRL source snapshots and their notices. `code/native_rh56_source/` supplies the native control/simulator Python source subset; the omitted assets and expert actor are still required for the original simulation paths.

After downloading the pinned handoff revision:

```bash
cd rh56-relocate-pcd
# Generated synthetic input only; no training, simulation rollout or hardware commands.
python examples/infer_sequence.py --self-check

# External offline inputs; choose a fresh output file.
python examples/infer_sequence.py --input /absolute/path/to/observations.npz \
  --output /absolute/path/to/new-action-means.npy
```

The recorded CPU acceptance has five passing tests and actual exit 0 for both CLI paths; the NPZ used for that acceptance was also synthetic. Complete model tensors matched the original state, the reference inference-chain maximum absolute difference was zero, and the model/BatchNorm state did not change during checks. This is loading/data-flow evidence, not an additional control-success or hardware result.

Read the downloaded `docs/TRAINING.md`, `docs/SIMULATION_DEPENDENCIES.md`, `requirements_training_wm.txt` and `training_sources.json` before a new run. The original WM/BC entrypoints still reproduce new training runs; they have no `--init-checkpoint` / `--init-policy` flags, and `--resume` is not a new-data fine-tuning interface. Their existing model/loss/optimizer loops were retained. Data, native assets/expert actor and the complete compatible legacy BC runtime are external inputs; this handoff does not certify a clean environment rebuild or a self-contained simulation distribution.

The policies remain reward-selected. Their associated online evaluations used 25 trajectories each:

| BC seed | Saved-policy eval index | Saved-policy SR | Curve Best-of-20 SR | Final head SR |
|---|---:|---:|---:|---:|
| 100 (primary) | 15 | 48% | 60% | 60% |
| 200 | 90 | 40% | 44% | 24% |
| 300 | 55 | 32% | 36% | 20% |

The downloaded encoder/projector produces 192-D features. BC expects the original FLARE fusion `[e(t-1)-e(t-2), e(t)-e(t-1), e(t)]` followed by 13-D proprioception: **589D→12D**. Read the package's `interface_contract.json` for coordinate frame, units, joint order, history reset and action mapping. The portable head returns raw deterministic means; clipping and hardware execution are separate.

The action normalizer was not stored numerically in the original checkpoints. It was recomputed for this release from the original 9000 training episodes using the original Torch FP32 mean/sample-standard-deviation formula; the action-input SHA matched the original production record. Its receipt is separate from the historical training acceptance. PCD encoding and frozen BC inference do not use this action z-score.

Use the model weights as initialization for a new fine-tuning or BC run. Exact optimizer/RNG/sampler resume and real-robot control remain unverified. The package omits external native robot assets/expert weights and hardware drivers; its baseline model sources retain the original training version, while its portable adapter is the later integration version. Neither the repository refactor nor this publication reran the six historical experiments. RGB weights are not included in this PCD release.
